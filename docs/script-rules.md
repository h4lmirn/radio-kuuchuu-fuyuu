# 台本の書き方（数字の読みと、圧縮しすぎないための決まり）

読み上げ文（`say`）を書くときの決まり。口調の型は [kazusa-style.md](kazusa-style.md)、JSON の形は [formats.md](formats.md) を見る。ここでは「数字の読み方」と「情報を詰め込みすぎないこと」だけを定める。

## 数字の読み方（例外なしで全部に適用）

`say` の数字は、**すべて1桁ずつ、ひらがなで書く**。位取りの読み（漢数字の読み）は使わない。

| 数字 | 読み |
|---|---|
| 0 | ゼロ |
| 1 | いち |
| 2 | に |
| 3 | さん |
| 4 | よん |
| 5 | ご |
| 6 | ろく |
| 7 | なな |
| 8 | はち |
| 9 | きゅう |

- 小数点は「てん」。0.9 → ゼロてんきゅう、1.2 → いちてんに、0.07 → ゼロてんゼロなな
- 単位（円、ドル、パーセント、おく、まん、件、問、年、月、日、時、秒、人、倍、店など）は、数字のうしろに言葉で付ける
  - 1999年 → いちきゅうきゅうきゅうねん
  - 594億 → ごきゅうよんおく
  - 1150億ドル → いちいちごゼロおくドル
  - 43% → よんさんパーセント
  - 24,000円 → によんゼロゼロゼロえん
- バージョン番号や型番も同じ。2.6 → にてんろく、27B → にななビー、7542 → ななごよんに
- 元の資料に「2万4千円」のような単位入りの表記があっても、`say` ではまず数字列（24000）に直してから桁読みにする。「にまんよんせんえん」とは書かない
- `show`（字幕・表示）は今までどおり普通の表記でよい。桁読みにするのは `say` だけ

### 例外：日付の月日

日付の月日だけは、従来の読みのままにする。`say` にも漢数字で書く（十一月十日、の形）。番組冒頭の日付もこれに含む。西暦の年は例外ではなく、桁読みのまま（1999年 → いちきゅうきゅうきゅうねん）。

理由：位取りの変換は書き手の暗算になり、桁落ちや単位の取り違えが起きる。桁読みなら数字を1文字ずつ写すだけで済み、間違いが起きても照合で見つけられる。

## 圧縮しすぎないための決まり

短くすることより、音だけで追えることを優先する。

- 1文に情報は1つ。製品名・変更点・数字を1文に詰めない
- 数字を言うときは、必ず「何の数字か」を言葉で付ける。対象の落ちた数字の並び（「パラメーターは約〜、動くのは〜だけ」のような形）にしない
- 音声に出す数字は、1つのニュースで原則1つまで（いちばん大事なもの）。残りの数字は `details` に置く
- 固有名詞（団体・製品・サービス）は、初出で半文の説明を付ける。名前だけを文頭に置いて始めない
- 因果と対比は接続詞で明示する（だから、でも、そのため）。事実を並べるだけにしない
- 専門用語は、言い換えるか、一言そえる
- 行数は3行に固定しない。3行で伝わらないなら4行に増やす

## 照合

台本を書いたら、音声を作る前に必ず実行する。

```sh
python3 tools/check_numbers.py episodes/<日付>-ja.json
```

`say` の数字読みと `show` の数字が食い違う行、`say` に位取りの漢数字やアラビア数字が残っている行を警告する。警告が出たら直してから次に進む。
